# ESRead v1 — definition and scope

This pins exactly what v1 is, so scope creep stays visible. The product vision lives in
`product.md`; this doc is the v1 contract downstream of it. Design decisions here were locked
in a planning interrogation (2026-06-25).

## Done line

v1 is "done enough" when (from `product.md` success criteria, plus the v1 additions below):

- A `.txt` and a `.epub` both parse and play across the full WPM range (continuously adjustable,
  not fixed presets) with no visible glitches.
- Books arrive by **SD-card sideload**: copy `.txt`/`.epub` into `/sdcard/books/` from a card
  reader, and they show up in the on-device picker. (Companion-app intake is v2.)
- Power cycle resumes the previous bookmark, in the right book, at that book's WPM, **paused**
  and ready — the device never auto-starts the book on boot. With no current book it boots to
  the **home menu**.
- The reader can rewind a sentence or to the paragraph start while reading.
- The screen **auto-rotates** right-side-up from the IMU regardless of how the device is held.
- The **off button powers the device down**, and the battery **charges over USB-C**.
- A battery percentage indicator is visible on screen.
- A non-technical user can pick up the device, press play, and read for 20 minutes unaided.

## Locked decisions

| Decision | Choice |
|----------|--------|
| Word timing | **Reedy-style variable** — base WPM × word-length factor + punctuation / paragraph pauses |
| Reading UI | **Focal word + ORP only** — one word with the ORP letter highlighted; the ORP letter is a **configurable fraction of the word** (default ~30%, Reedy-style) **anchored at the screen's horizontal center** (the eye-rest point). The word shifts around that anchor; it is not centered as a whole. |
| Render path | **LVGL** on AXS15231B (QSPI), landscape 640×172 |
| Char coverage | **Latin-1 + Latin-Extended-A + common punctuation** (smart quotes, em/en dash, ellipsis, NBSP); tokenize on Unicode codepoints, never bytes |
| v1 formats | **`.txt` + `.epub`** (`.fb2` / `.mobi` are post-v1) |
| Rewind | **Back one sentence + back to paragraph start** (no forward skip, no full scrub) |

## In v1

- **Text pipeline:** `.txt` and `.epub` → `text_stream` → `rsvp`.
- **Variable timing** with ORP, WPM continuously adjustable across a configured range (min / max /
  step are `constexpr`/Kconfig, e.g. 100–1000 by 25, default 300) — not fixed presets.
- **ORP screen** (focal word; ORP letter at a configurable word-fraction, anchored at screen center; LVGL).
- **Glyph coverage** — the reading font renders ASCII + Latin-1 + smart punctuation (curly quotes /
  apostrophes, en/em dashes, ellipsis), so real English / Western-European books show correctly,
  not boxes. Full Unicode BMP is out (flash). See `dev/active/glyph-coverage/PLAN.md`.
- **Rewind navigation** — back-sentence, paragraph-start.
- **Bookmark resume**, per book, surviving reboot.
- **Multiple books in progress** — each remembers its own position.
- **Per-book WPM** — each book remembers its last-read speed.
- **Idle screen-sleep (paused only)** — while **playing**, the device never auto-pauses; reading
  needs no touches, so you can read untouched as long as you like (pausing is a tap or end-of-book).
  Only once **paused**, an inactivity timer dims the screen, then turns it off to save power; a
  touch wakes it at the same place, nothing lost. (Deep-sleep power management is post-v1.)
- **Book intake** — **SD-card sideload only**. Drop `.txt`/`.epub` into `/sdcard/books/` from a
  card reader; the picker lists them. No network intake in v1; the companion app is v2.
- **Home menu** — a default home screen shown when no book is open (M6). Boot resumes the current
  book if there is one, else lands here (M7).
- **Touch controls** — play/pause, WPM up/down, rewind.
- **On-device book picker** — browse `/sdcard/books/`, see in-progress state, tap to open.
- **IMU auto-rotate** — the screen flips right-side-up from the QMI8658 orientation (M8).
- **Off-button power-down** — the physical off button cuts power cleanly via the board's power
  latch (M9).
- **USB-C charging** — the charge path is enabled and charge status is readable; the on-screen
  battery icon reflects it (M10).
- **On-device settings UI** — change reading speed (WPM), **which letter is highlighted (ORP
  pivot %)**, ORP color, font size, brightness/night mode, all on the device. Settings persist in
  NVS. Consequence: ORP pivot is a tunable **percentage of the word**, not a fixed formula —
  `rsvp` reads the pivot fraction and `display` reads color/font from the settings store.

- **Boot into paused state** — on power-up the device resumes the last book at its bookmark but
  stays **paused**; the reader taps play to start. Never auto-plays.
- **Battery percentage icon** — on-screen indicator, read from the board's battery ADC.

## Controls and power model (hardware reality)

- **All app commands are touch.** Play/pause is a tap on the screen; WPM, rewind, picker, and
  settings are all on-screen (capacitive touch, AXS15231B over I²C). Serial stays a dev shortcut.
- **Three physical buttons: boot, reset, off.** Boot and reset are **never used by the app**.
  **Off powers the device down** via the board's power latch (M9). Even so, a dying battery can
  still cut power at any moment, so bookmark persistence relies on **periodic SD writes** (M2),
  not only a flush at shutdown — the latch must not be the only thing standing between a read
  position and a power loss.
- **Reprovisioning** uses the existing BLE Wi-Fi provisioning flow (creds in NVS). Wi-Fi stays
  active on boot for time sync and future use, but nothing in v1 reads the network for book
  intake.

## Architecture notes that bind the milestones

These hold across every milestone; each PLAN restates the slice it touches.

- **`sd` is a thin mounter, not a file API.** SD mounts as a FAT VFS at `/sdcard`. Other
  components do **not** include `sd` (leaf rule 3) — they read/write with POSIX `fopen` on
  `/sdcard/...`. `sd`'s job is mount/unmount + mount status, and it must **degrade, not panic**
  (today it `ESP_ERROR_CHECK`s in its constructor — fixed in M0).
- **`StreamPosition` is the resume currency.** `text_stream` exposes a serializable position
  and can `seek` back to it. For `.txt` it maps to a byte offset into the file; for `.epub` to
  `(spine_index, byte offset)`. `bookmark` stores it opaquely; only the parser/text_stream
  interpret it. Defined in M1, consumed in M2.
- **Settings are read, not hardcoded.** ORP pivot % + color, WPM, font size, brightness live
  in an NVS-backed `settings` store (M5). `rsvp` reads the pivot fraction; `display` reads
  color/font. M1/M4 take these as injected config so M5 only wires the store in — no rework.
- **`main/` owns all wiring.** It mounts SD, picks the parser by extension, injects the
  paragraph source into `text_stream`, the word source + frame sink into `rsvp`, drains the
  frame queue (serial in M1, `display` in M4), routes `controls` events, and persists via
  `bookmark`. Components never reach across to each other.

## v1 work breakdown (ordered)

Sequenced so nothing is built before what it depends on. Each milestone ends with a green
`idf.py build`; each gets a `dev/active/<slug>/PLAN.md` before coding (rule 7).

0. **M0 — Foundation: boot + SD cleanup.** Make Wi-Fi failure non-fatal so the device runs
   offline (architecture boot sequence); refactor `sd` off its Spotify/Google OAuth carryover
   into a fallible, degrade-on-failure mounter with `constexpr` pins; lay down the `main/`
   orchestration skeleton + task topology. Unblocks everything. See
   `dev/active/foundation-boot-sd/PLAN.md`.
1. **M1 — Text pipeline over serial.** `parser_txt` (with `seek`) + `text_stream`
   (rewind-capable, serializable `StreamPosition`) + `rsvp` (config-driven ORP), frames printed
   to UART. Proves the spine with no display. See `dev/active/text-pipeline-serial/PLAN.md`.
2. **M2 — Bookmark store on SD.** Per-book records keyed by book id, each holding
   `StreamPosition` + last WPM + timestamp. Batched writes (every 10–30 s / on pause).
   Multiple-books-in-progress falls out of this. See `dev/active/bookmark-store/PLAN.md`.
3. **M3 — `.epub` parser.** `miniz` (in IDF, no new dep) to unzip; walk spine; strip XHTML to
   paragraphs; same `text_stream` + `StreamPosition` contract. See
   `dev/active/epub-parser/PLAN.md`.
4. **M4 — Display bring-up.** LVGL + AXS15231B + bundled font + `display` task; swap the serial
   sink for the screen; a `battery` reader (ADC) + on-screen battery icon; boot shows the last
   book **paused**. See `dev/active/display-bringup/PLAN.md`.
5. **M5 — Controls + book picker + settings.** **Touch-only** play/pause (tap), WPM up/down,
   rewind (back-sentence, paragraph-start); list `/sdcard/books/` with in-progress state;
   NVS-backed `settings` store + on-device settings UI (WPM, ORP pivot % + color, font size,
   brightness); idle timer runs only while paused → dim then screen off (never pauses an active
   reader); on-screen reprovision trigger. See `dev/active/controls-picker-settings/PLAN.md`.
6. **M6 — Home menu.** A default home screen shown when no book is open: entry points to the
   picker and settings, and the place the device sits with an empty library. The home ↔ reading ↔
   picker ↔ settings state machine in `main/`. See `dev/active/home-menu/PLAN.md`.
7. **M7 — Boot target state.** A persisted "current book" pointer in the settings (NVS) store:
   boot resumes it if set, else opens the home menu (M6). Set on open, cleared on finish or
   close-to-home, so a finished book does not reopen. See `dev/active/boot-target-state/PLAN.md`.
8. **M8 — IMU auto-rotate.** Read orientation from the QMI8658 and rotate the LVGL display so the
   focal word is always right-side-up, with hysteresis so small tilts don't flip it. See
   `dev/active/imu-auto-rotate/PLAN.md`.
9. **M9 — Off-button power-down.** Drive the board's power latch so the physical off button cuts
   power cleanly; flush the bookmark on the way down where the latch gives us the window. Wiring
   from the vendor `07_BATT_PWR_Test` example. See `dev/active/off-button-power/PLAN.md`.
10. **M10 — USB-C charging.** Enable the charge path via the TCA9554 expander (EXIO6) and read
    charge status, so the battery charges from USB-C and the M4 battery icon reflects charging.
    See `dev/active/usb-c-charging/PLAN.md`.

Companion-app intake (the old M6) is **out of v1** — parked in `dev/proposed/companion-intake/`.
