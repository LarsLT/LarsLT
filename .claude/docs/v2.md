# ESRead v2 — definition and scope

This pins exactly what v2 is, so scope creep stays visible. The product vision lives in
`product.md`; the shipped v1 contract is in `v1.md`; this doc is the v2 contract downstream of
both. Scope and sequencing here were locked in a planning session (2026-07-04).

v2 is the "final version" ESRead has always pointed at: the device stops needing a card reader.
A non-technical reader receives a book from a relative's phone and reads it, and the phone and the
device stay in sync.

## Done line

v2 is "done enough" when:

- A book pushed from the phone lands in `/sdcard/books/` and shows up in the picker with **no SD
  card handling** — over Wi-Fi at home, over BLE when away.
- Pairing is a **one-time BLE step**; after that the phone just sends books. Unauthenticated
  writes are silently rejected.
- `.fb2` and `.mobi` parse and play like `.txt`/`.epub`. A `.pdf` converted **on the phone** to
  plain text plays too (no on-device PDF).
- The picker shows **word-progress %** and **time-to-finish** per in-progress book.
- Reading **position, library, and stats** sync two-way between device and phone.
- Reading **stats** (words read, time spent, books finished) are visible on the phone.
- ORP colour is picked on a **colour wheel** with a live preview, not a hex cycle.
- Tapping a word in the paused **context strip seeks** there.
- The non-technical user receives a book, presses play, and reads — no card, no menus, no help.

## Locked decisions

| Decision | Choice |
|----------|--------|
| Release shape | **Everything in one v2 release** — companion intake + two-way sync + on-device polish + more parsers. Sequenced into milestones below. |
| Companion app | **Separate repo, but a v2 deliverable.** Device firmware dev **pauses** while the Android app is built against the Phase B protocol, then resumes for Phase C. |
| Transport | **Hybrid.** Pair once over BLE (the trust anchor) and provision Wi-Fi; transfer over **Wi-Fi LAN at home**, **BLE chunked fallback** away. One pairing-derived secret authenticates both paths. |
| Flash / partitions | **Already resolved in v1.** A custom `partitions.csv` shipped with a 4 MB factory app slot on the 16 MB flash; the v1 binary is ~1.3 MB (68% free). M0 shrinks to confirming the Phase B stack fits by building it. |
| PDF | **Phone-side conversion in the companion app** → ships plain text to the device like any `.txt`. No on-device PDF parser (unchanged from `product.md`). |
| v2 formats | `.fb2` + `.mobi` on-device; `.pdf` via phone-side conversion. (`.txt`/`.epub` already shipped in v1.) |
| `total_words` | Companion computes it **once at upload** and ships it as metadata; the bookmark record gains a `total_words` field. This is what lights up the picker %/ETA. |
| Sync | **Two-way** (position / library / stats), builds on intake, lands **after** the app exists. |
| Transport security | **Unresolved:** PSK-TLS vs libsodium AEAD for the LAN socket — pick at Phase B design time. Both must key off the pairing secret (S2/S8). |

## In v2

- **Companion book intake** — the full hybrid transport: BLE pairing + Wi-Fi provisioning, Wi-Fi
  LAN transfer at home, BLE chunked fallback away, mDNS discovery, atomic temp-then-rename into
  `/sdcard/books/`. Design detail in `dev/proposed/companion-intake/PLAN.md`.
- **Android companion app** (separate repo) — pairs with the device, sends books, converts PDF to
  text phone-side, and (Phase C) syncs. This doc specs only the **on-device protocol** the app
  targets; the app is built during the device-dev pause.
- **Two-way sync** — reading position/bookmarks, library, and reading stats sync while the phone
  and device are connected. (Intake is one-way send; sync is bidirectional.)
- **Reading stats / history** — words read, time spent, books finished, tracked on-device and
  surfaced on the phone.
- **`.fb2` parser** — XML, structurally simple; same `text_stream` + `StreamPosition` contract.
- **`.mobi` parser** — older Amazon format, on-device; more complex but in scope.
- **Picker word-progress % + time-to-finish** — from `total_words` shipped by the companion at
  upload. Was deferred from v1 because it needs a full-book word count.
- **ORP colour wheel** — a dedicated colour screen with a hue wheel and a live preview word,
  replacing the v1 hex-cycle. `dev/proposed/orp-color-wheel/PLAN.md`.
- **Context tap-to-seek** — tapping any word in the paused context strip seeks the reading
  position there; the strip becomes a scrubber. `dev/proposed/context-tap-seek/PLAN.md`.

## Out of v2 (v3+)

- **Deep-sleep power management.** v1/v2 dim-then-off the screen while paused; true deep sleep is
  still later.
- **IMU gestures** (tap/flick secondary controls).
- **On-device PDF** — stays phone-side conversion only.
- **Audio / TTS.**
- **Cloud sync / remote config / telemetry** — sync is phone↔device LAN/BLE only, no cloud.
- **Multi-user.**

## Open risks (resolve inside the owning milestone)

- **Flash budget: downgraded** (2026-07-04). The 4 MB app slot already exists and v1 uses ~1.3 MB,
  so NimBLE + Wi-Fi + provisioning + mDNS + TLS (~0.7-1 MB) fits on paper. M0 confirms by building
  the stack, no partition work expected.
- **Transport security choice** (PSK-TLS vs libsodium AEAD) — pick before writing socket code in
  Phase B; both key off the pairing secret.
- **BLE + Wi-Fi radio coexistence** on the ESP32-S3 — verify throughput and stability with both
  stacks up; keep BLE advertising minimal while a Wi-Fi transfer runs.
- **Sync conflict model** — when the phone and device both moved a bookmark, which wins? Decide the
  merge rule (last-write-wins by timestamp is the likely default) at the M9 design.

## Architecture notes that bind the milestones

These hold across v2; each PLAN restates the slice it touches. They extend the v1 notes in
`v1.md`, which still apply (`sd` is a thin mounter, `StreamPosition` is the resume currency,
settings are read not hardcoded, `main/` owns all wiring).

- **Everything off the network is untrusted (S5).** Authenticate before accepting, validate
  lengths, cap sizes, sanitize filenames, write atomically. A malformed or oversized push fails
  cleanly and leaves no file, never crashes the device.
- **The pairing secret is the one trust root.** Derived once over BLE, stored in **NVS**, never on
  SD, never logged (S3/S4/S8). Both transports and sync authenticate against it.
- **Intake and transfer land in leaf components.** `main/` orchestrates; `companion_pair`,
  `book_intake_ble`, `book_intake_wifi` are leaves that don't include each other (rule 3).
- **`total_words` extends the bookmark record, not the position contract.** The picker reads it for
  %/ETA; the resume `StreamPosition` is unchanged.
- **Sync is a `main/`-owned reconciliation**, not a component reaching across others. It reads the
  bookmark store and library list, exchanges them over the authenticated channel, and writes back.

## v2 work breakdown (ordered)

Sequenced so nothing is built before what it depends on. Each milestone ends with a green
`idf.py build` (host unit tests where the parser/pipeline is touched); each gets a
`dev/active/<slug>/PLAN.md` before coding (rule 7). Milestones still parked as sketches live in
`dev/proposed/`; promote with `git mv` when they go active.

### Phase A — De-risk + cheap device-only wins

0. **M0 — Flash budget confirm.** The 4 MB app slot already shipped in v1 (~68% free). Build with
   the Phase B network stack enabled and confirm headroom; also pin `network_provisioning` / `mdns`
   / `libsodium` as direct deps in `main/idf_component.yml` (today they are only transitive via
   arduino-esp32). Gates Phase B. Do it first. *(PLAN to be written when active.)*
1. **M1 — ORP colour wheel.** Dedicated colour screen, hue wheel + live preview, writes `orp_color`
   to settings. Self-contained UI, no flash risk. `dev/proposed/orp-color-wheel/`.
2. **M2 — Context tap-to-seek.** Per-word touch targets on the paused strip carrying their
   `StreamPosition`; tap seeks and re-renders; center tap plays from there. Turns the strip into a
   scrubber. Fold in the `bookmark-resume-stale-position` fix while in this code.
   `dev/proposed/context-tap-seek/`.
3. **M3 — `.fb2` parser.** XML → paragraphs → same `text_stream` + `StreamPosition` contract. Host
   unit tests. Independent of the network. *(PLAN to be written when active.)*
4. **M4 — `.mobi` parser.** On-device MOBI → paragraphs, same contract. More complex; host unit
   tests. Independent of the network. *(PLAN to be written when active.)*

### Phase B — On-device companion protocol (the spine the app targets)

5. **M5 — Pairing + Wi-Fi provisioning over BLE.** `companion_pair`: BLE GATT pairing service, key
   agreement, secret → NVS, Wi-Fi creds via `network_provisioning`, silent reject of unauthorized
   writes. `dev/proposed/companion-intake/` (pairing section).
6. **M6 — BLE chunked transfer.** `book_intake_ble`: authenticated header + chunked body → temp
   file → hash verify → atomic rename into `/sdcard/books/`. The offline/away path.
7. **M7 — Wi-Fi LAN transfer + mDNS.** `book_intake_wifi`: advertise `_esread._tcp`, authenticated
   socket server (PSK-TLS or AEAD, decided here), same temp/rename path. The at-home path.
8. **M8 — `total_words` metadata → picker %/ETA.** Accept and store `total_words` from the intake
   header; bookmark gains the field; picker shows word-progress % and time-to-finish.

### ⏸ Pause device dev → build the Android companion app

Built in a **separate repo** against the Phase B protocol (pairing, BLE + Wi-Fi transfer framing,
`total_words` metadata). Adds phone-side **PDF → text** conversion. Device firmware work resumes at
Phase C once the app can pair and push.

### Phase C — Sync + stats (needs the app)

9. **M9 — Two-way sync.** Reconcile reading position/bookmarks and the library list over the
   authenticated channel; pick the conflict rule (likely last-write-wins by timestamp).
   *(PLAN to be written when active.)*
10. **M10 — Reading stats/history.** Track words read, time spent, books finished on-device; sync
    and surface them on the phone. *(PLAN to be written when active.)*

### Rolling cleanup (not gated milestones)

Opportunistic, done when the surrounding code is next touched, not in a big-bang pass:

- **Component READMEs** — the per-leaf README convention. `dev/proposed/component-readmes/`.
- **Error `to_string()` codegen** — reduce the hand-written switch boilerplate.
  `dev/proposed/error-to-string-codegen/`.
- **Chunked-read tuning** — only if profiling shows SD churn. `dev/proposed/chunked-read-tuning/`.
