# LarsLT — GitHub profile README

This is the special **`LarsLT/LarsLT`** repository. Its `README.md` is what renders at
the top of https://github.com/LarsLT. The whole point of this repo is that profile page:
a personal landing card (banner, typing animation, badges, tech stack, GitHub stats) plus
self-updating animations generated by GitHub Actions.

There is **no application to build and nothing to flash.** The "product" is a page that
renders correctly on GitHub. Treat visual correctness on the live profile as the
definition of done.

## What's in the repo

- **`README.md`** — the profile itself. Markdown with inline HTML (`<div align=center>`,
  `<picture>`), shields.io / skillicons.dev / capsule-render / readme-typing-svg badges,
  and github-readme-stats cards.
- **`.github/workflows/snake.yml`** — builds the Platane/snk contribution snake and pushes
  the generated SVGs to the **`output`** branch; the README embeds them from there.
- **`.gitignore`** — tracks the shared `.claude/` config, ignores `.claude/settings.local.json`.

Generator tooling (like the planned space-map, see `.claude/dev/proposed/space-map/`) is
a small **Go** program run by Actions on a cron, writing an SVG to its own branch. That's
the only code this repo grows — Go + Markdown/SVG.

## How GitHub renders this page (the constraints that matter)

- **Images go through GitHub's camo proxy.** Every image URL in the README is fetched and
  cached server-side. Dynamic SVG services still work, but they can be slow, rate-limited,
  or cached stale. The only test that counts is loading github.com/LarsLT and looking.
- **Scripts are stripped; animation must be CSS-only.** GitHub sanitizes embedded SVG:
  no `<script>`, no external references. Motion uses CSS `@keyframes` / `offset-path`
  inside `<style>`, never SMIL `<animateMotion>` or JS. The snake proves this path works.
- **Light/dark theming uses `<picture>`** with `media="(prefers-color-scheme: dark)"`,
  or a service that offers a dark theme param.
- **Generated SVGs live on a dedicated branch, never on `main`.** Snake → `output`. A new
  generator gets its **own** branch (the space-map plan uses `space`) so workflows don't
  clobber each other's output. `main` holds source only.

## Hard rules (do not violate)

1. **Never break the profile render.** Before changing README markup or a badge URL,
   know how it renders through camo. When unsure, keep the change small and reversible.
2. **SVG animations are CSS-only.** No `<script>`, no SMIL, no external fetches inside the
   SVG — camo blocks and GitHub strips them. See `.claude/docs/profile-readme.md`.
3. **Generated output goes to its own branch, not `main`.** Don't commit build artifacts
   (SVGs, `dist/`) onto `main`; the workflow publishes them to `output` / `space` / etc.
4. **Keep personal facts accurate.** Name, contact email, and links in the README are
   real and public. Don't invent or alter them without being asked.
5. **Git.** Single-branch: always work on `main`, never a side branch, never push. Commit
   in small units with one-line Conventional Commit messages (no scope/emoji/attribution).
   The user pushes. See `.claude/rules/git.md`.
6. **Write plans to disk.** For any multi-step feature (a new animation, a workflow),
   write `.claude/dev/proposed/<slug>/PLAN.md` (or `active/` once building) before
   implementing — don't keep plans only in chat. See `.claude/dev/README.md`.

## Where to read before acting

| Task | Read first |
|------|------------|

| A new generated animation or workflow | `.claude/dev/proposed/space-map/PLAN.md` (worked example), `.claude/docs/profile-readme.md` |

## Folder map (.claude/)

```
.claude/
├── CLAUDE.md          # this file — always loaded
├── README.md          # human-facing overview of this config
├── settings.json      # shared (tracked) — perms, marketplaces, enabled plugins
├── settings.local.json# personal (gitignored) — extra perms
├── docs/              # durable knowledge (profile-readme.md)
├── dev/               # feature notes: proposed/ → active/ → closed/
├── hooks/             # project-local hooks (shared ones ship via claude-kit)
├── marketplaces/      # consumes the LarsLT/claude-kit marketplace
├── plugins/           # repo-local plugins (currently none)
└── rules/             # hard rules (git.md)
```

## Shared config (claude-kit)

Skills and hooks come from the private `LarsLT/claude-kit` marketplace, declared in
`settings.json`. Enabled here: `core` (language-agnostic writing/planning skills) and
`go` (gofmt/goimports + comment-lint hooks, for the generator tooling). Change a shared
file in `claude-kit`, then run `/plugin` to pick it up — don't copy it back into this repo.
